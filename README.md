# СППР оцінки ризиків та інвестиційної привабливості ІТ-стартапів

Система підтримки прийняття рішень до магістерської роботи. Для кожного стартапу вона рахує
оцінку **Score ∈ [0, 100]** і категорію (низька / помірна / висока / дуже висока) як зважену суму трьох компонентів:

```
Score = w₁·M(X) + w₂·F(Y) + w₃·G(D)
```

| Компонент | Що це | Модуль |
|---|---|---|
| **M(X)** | ML-прогноз за кількісними показниками компанії (scikit-learn) | `src/ml_module.py` |
| **F(Y)** | нечітка оцінка сприятливості за 4 експертними оцінками, каскад Мамдані з 27 правил (scikit-fuzzy) | `src/fuzzy_module.py`, `data/fuzzy_rules.json` |
| **G(D)** | оцінка умов угоди (опційно) | `src/deal_module.py` |
| **w₁, w₂, w₃** | ваги профілю інвестора: пресет або власне попарне порівняння (метод AHP, власна реалізація на numpy) | `src/ahp_module.py` |

## Встановлення

Потрібен Python 3.10.

```bash
python3.10 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### Дані та модель

Датасет `data/raw/startups_dataset.csv` (8000 стартапів, 17 колонок, з пропусками) і навчена модель
`models/model.pkl` входять до репозиторію, тому після клонування й встановлення залежностей система працює одразу.

Модель можна створити заново: у застосунку увімкніть «Режим адміністратора» в бічній панелі й натисніть **Перенавчити**
(≈ 1 хв: 5-fold крос-валідація трьох моделей + фінальне навчання). Попередня версія зберігається як `models/model_prev.pkl`
(у git не потрапляє). Без файлу моделі застосунок стартує, але екран «Новий аналіз» підкаже, що робити.

> На цьому датасеті Success Score реально залежить від ознак: тестовий R² ≈ 0.73–0.75 (найкраща модель —
> Gradient Boosting, R² 0.746, RMSE 13.1 на шкалі 0–100). Попередній датасет (Kaggle, Global Startup Success) був шумом, R² ≈ 0 — це описано в
> роботі. Обидва датасети, найімовірніше, синтетичні, тож R² відображає закономірності генератора, а не
> реального ринку.

## Запуск

Усі команди — з кореня проєкту.

```bash
streamlit run src/app.py                 # відкриється http://localhost:8501
```

SQLite-база створюється автоматично: `data/processed/startup_dss.db`.

## Екрани

| Екран | Що робить |
|---|---|
| Новий аналіз | форма: показники компанії, 4 експертні оцінки (0–10), опційні умови угоди |
| Результат аналізу | Score, категорія, радар експертних оцінок, розбивка ML/Fuzzy/Deal з вагами, формула; блок **«Деталі розрахунку»** з усіма проміжними значеннями |
| Історія аналізів | таблиця збережених аналізів, позначка відповідності профілю пошуку |
| Порівняння | 2–3 аналізи поруч |
| Профіль інвестора | пресет ваг (conservative / balanced / growth) або попарне порівняння за шкалою Сааті з перевіркою CR |
| Звіт | PDF із результатом і деталями розрахунку |
| Адміністратор | перемикач у бічній панелі, без логіну: **Перенавчити** модель і таблиця 27 правил Fuzzy з редагуванням висновків |


### «Деталі розрахунку»

Для кожного аналізу зберігаються й показуються (на екрані та в PDF): сира й перемасштабована ML-оцінка;
`execution_capability`, `market_attractiveness`, `F_raw` і нормалізоване `F`, найсильніші спрацьовані правила;
ваги AHP та CI/CR; три часткові оцінки Deal; підсумкова формула з підставленими числами.
Деталі пишуться в `analyses.details_json`; аналізи, збережені до їх появи, показують «Деталі недоступні».

### Режим адміністратора

- **Перенавчити**: навчає Linear Regression, Random Forest і Gradient Boosting на 80 % датасету, обирає найкращу
  за 5-fold CV RMSE (тест лишається чистим) і зберігає її як `models/model.pkl` (попередню — як `models/model_prev.pkl`), показує test- і train-метрики.
- **Правила Fuzzy**: змінюється лише висновок правила (кожна комбінація умов має рівно одне правило). При
  збереженні межі нормалізації F(Y) перераховуються по сітці 5⁴ = 625 комбінацій, попередній файл лишається як
  `data/fuzzy_rules.prev.json`. Правила, що роблять вихід сталим, відхиляються з відкатом.
- Зміни діють на нові аналізи; збережена історія не перераховується.

## Можливі проблеми

- `ModuleNotFoundError` — не активовано віртуальне середовище або не виконано `pip install -r requirements.txt`.
- Помилка `dlopen … scipy … _propack` на старих версіях macOS — це несумісність збірки scipy; у `requirements.txt` зафіксовано `scipy==1.14.1`, яка працює.
- Порт 8501 зайнятий — `streamlit run src/app.py --server.port 8502`.
